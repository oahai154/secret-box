# 恢复密钥与 v2 存储格式（DEK 密钥包装）

忘记主密码在 v1 格式下意味着数据永久不可恢复（scrypt+AES-256-GCM，无任何旁路）。为产品设计兜底方案：引入**恢复密钥**——首次设置时强制生成并要求用户抄写确认的 128 位 base32 分组码，忘记主密码时凭它解密数据并重设主密码。

恢复密钥要求条目不再直接由主密码派生密钥加密，因此采用 **DEK 密钥包装**架构：随机生成数据加密密钥（DEK）加密全部条目，DEK 被两份包装存盘——主密码派生 KEK 包装一份、恢复密钥派生 KEK 包装一份。改主密码由此从"全库重加密"降为"重新包装 DEK"。快照导出同步采用同构的 v2 包装，恢复链全覆盖。

## Considered Options

- **密保问题重置**：在零知识本地加密场景中，问题答案就是第二把主密码，且熵极低——诚实作答则"认识你的人"可进库，胡乱作答则自己会忘。拒绝。
- **OS 钥匙链 / 云端托管**：绑定单台设备或破坏"数据不出本机"。拒绝（OS 托管可作未来增强，不互斥）。
- **不迁移、原地重加密**：后者在中途崩溃时会把用户唯一的库改坏一半。改为建新 v2 库 + 导入 + 确认成功后归档旧文件，原子性白送。

## Consequences

- 打破与 Go 版的字节兼容（ADR 0002 的"推迟"条款就此启用）：v1 主库与 v1 快照在新版中均为**只读导入源**，v1 写路径删除，不留兼容写后门。
- 存量库升级走**强制升级向导**，不设跳过：启动检测到 v1 库 → 输主密码 → 建 v2 新库并导入全部数据与历史版本 → 强制生成恢复密钥 → 成功后旧文件改名归档留作后路。
- 恢复密钥仅解锁后可见/可复制；可重生成（需主密码，旧钥立即作废）；救援流程（锁屏"忘记主密码"→输恢复密钥→重设主密码）之外**不设任何其他旁路**——无密保问题、无验证码、无找回。
- 恢复密钥与主密码地位平等：丢失恢复密钥同样无法找回数据，UI 必须如实告知此模型。
