# 明文 CSV 导出（一键迁出）

用户想把数据迁往其他密码管理器（Bitwarden、Chrome、KeePass 等），或想在表格软件里通览自己的数据时，现有唯一出口是快照——那是加密文件、需要另设迁移口令、且只有 SecretBox 自己能读。为此新增**明文导出**：解锁后一键生成 UTF-8 CSV（标题、分类、内容、备注四列，不含历史版本），经系统"另存为"对话框落盘。与快照分工明确：快照是可还原的加密备份，明文导出是单程迁出，不设对应的导入路径。

数据模型决定了 CSV 的列：条目没有独立的账号/密码字段，只有单一的 value 自由文本，故不存在 `login_username`/`login_password` 这样的拆分列，value 原样导出一列。

## Considered Options

- **不加此功能（安全最大化）**：数据属于用户，锁死出口只会把用户逼向截屏、手抄，或干脆不选 SecretBox。接受，但以警示与文案约束风险。
- **JSON 导出**：字段最全，但表格软件打开体验差、其他密码管理器不直接认，与"迁出"目的错位。CSV 是业界事实标准。拒绝（未来可并存，不互斥）。
- **含历史版本**：其他工具没有对应概念，多行或多列都会破坏"每行一条目"的干净结构；完整备份已由快照承担。拒绝。
- **前端生成 CSV**：解锁后的前端已持有全部明文，纯前端实现最省事；但违反"安全敏感逻辑只在 Rust"的分层约定，且"锁定态拒绝一切明文读取"的不变量会从 Rust 层强制退化为 UI 约定。拒绝——新增 `export_csv` 命令，`require_unlocked` 在 Rust 层强制。

## Consequences

- 一次点击即产生全库明文文件，这是产品安全姿态的实质放宽。导出前以模态确认如实警示（"任何拿到此文件的人都能读取全部内容"），但**不重输主密码**：已解锁会话本就可见全部明文，重输只是仪式感、不增加实质安全性。
- 导出不含历史版本；为防用户误当完整备份，导出区文案须指明"完整备份请用快照导出"。
- Windows 上 Excel 打开无 BOM 的 UTF-8 CSV 会乱码，导出内容须带 BOM；CSV 转义遵循 RFC 4180（逗号/引号/换行用引号包裹转义）。
- 导出的文件不属于任何应用内数据管理范围（"清除痕迹"只清本地库），文件产生后的生命周期完全归用户负责，UI 文案须如实说明。
