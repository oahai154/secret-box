# 06 — 存量 v1 库强制升级向导

**What to build:**
启动时检测到 v1 库（含便携模式指定的自定义路径）即被升级向导拦截：输入主密码 → 在旁边新建 v2 库 → 全部条目与历史版本导入 → 强制走恢复密钥生成确认（复用 02 流程）→ 全部成功后旧文件改名归档留作后路。不做原地重加密；中途任何失败旧库原样保留、可重试。拒绝升级则无法进入主界面（v1 在新版中只读）。依据 ADR-0003。

**Blocked by:** 02 — 恢复密钥生成与强制确认；05 — 快照 v2

**Status:** done

> 实施说明：
> - 检测：`status` 响应新增 `legacy` 字段（has_password && !is_v2），App.svelte 据
>   此在渲染树中把升级向导放在解锁页之前——**无跳过路径**，完成升级（含恢复密钥
>   确认）前无法进入主界面。导入/清除痕迹后 `handleSessionReset` 重新拉取 status
>   刷新 legacy（导入 v1 快照的库同样会被向导拦截，符合"v1=只读导入源"）。
> - `upgrade_v1(password)` 四步：① 验主密码并收割全部条目+历史版本明文；
>   ② checkpoint 后关闭旧库，主文件改名 `<path>.v1.bak` 归档（Windows 锁重试，
>   遗留归档直接覆盖）；③ 新建 v2 库：setup_master_password → 明文用新 DEK
>   重加密构造 Snapshot → restore_from_snapshot（保留原时间戳与版本号）→
>   生成恢复密钥并落盘；④ 会话置为解锁态，返回 recovery_key，前端接
>   RecoveryKeyView 强制确认后进主界面。
> - 原子性：③ 任何失败 → 删除半成品新库文件 → 归档改名回原名 → 重开旧库进
>   状态，旧库全程未动可重试；归档失败（连改名都没成功）→ 旧库原样未动。
> - 测试：Tauri 端到端（golden v1 fixture：legacy 标记 → 错误密码可重试 →
>   升级 → v2+恢复密钥+归档存在 → 3 条目与版本数、明文逐条一致 → 救援链可用）；
>   Playwright `upgrade-wizard.spec.ts`（拦截无跳过、错误密码、成功 → 强制确认 →
>   数据完整）。
