# 02 — 恢复密钥生成与强制确认

**What to build:**
首次设置主密码后强制进入恢复密钥页：生成 128 位 base32 分组码（字符集去除 0/O/1/I，分组连字符分隔），全屏展示 + 一键复制 + 用户完整重输一遍 + 勾选"已保存到安全的地方"，未完成确认无法进入主界面；DEK 的第二份包装（恢复密钥 KEK）同时落盘。依据 ADR-0003。

**Blocked by:** 01 — v2 核心架构：DEK 生成与密钥包装

**Status:** done

> 实施说明：
> - 核心新增 `recovery.rs`：恢复密钥为 20 随机字节（160 位熵，高于 128 位要求）
>   → 自实现 base32 编码（字符集 `23456789A-Z` 去 I/O，无歧义）→ 32 字符分 8 组
>   连字符分隔；`normalize_recovery_key` 归一化（大写、去分隔符），抄写差异不影响验证。
>   编码正确性由"编码可无损解码回原字节"测试保证。
> - `db.rs`：`set_recovery_key(recovery_key, dek)` 用恢复密钥派生 KEK（独立随机盐
>   `recovery_salt`）重新包装 DEK 写 `wrapped_dek_recovery`，重置即旧码作废；
>   `unlock_with_recovery_key` 解包装返回 DEK（与主密码解锁等价），错误归一化后
>   报 `RecoveryWrong`（"恢复密钥不正确"）；`has_recovery_key` 供 UI 判断。
> - Tauri：`setup_password` 响应扩展为 `{ok, recovery_key}`——设置主密码的同时
>   生成恢复密钥并落盘。若用户在确认前退出应用，恢复密钥已生效（可在设置中
>   查看挽回，工单 04），无安全损失。
> - 前端：新增 `RecoveryKeyView.svelte` 强制确认页——分组码展示 + 复制 + 重输
>   （归一化比对，与后端规则一致）+ 勾选确认，按钮在三者齐备前禁用；无跳过路径
>   （`App.svelte` 中该页优先于解锁页渲染）。`ipc.ts` 的 `setupPassword` 返回
>   `SetupResult`。
> - 测试：核心 `dek.rs` 增加恢复密钥回环（小写无分隔符输入通过、错误码拒绝、
>   重置后旧码作废）；Tauri 增加设置流端到端；Playwright 新增
>   `recovery-setup.spec.ts`（强制停留、错误重输被拒、归一化比对通过、剪贴板）。
>   注意：原工单写"128 位熵"，实际取 20 字节 = 160 位熵以获得整除的 8×4 分组。

- [x] 恢复密钥为 128 位熵、base32 分组码格式，随机生成无重复可再现性
- [x] 首次设置流程强制经过恢复密钥确认页，跳过/关闭即停留在该页
- [x] 重输不匹配时无法继续；匹配后恢复密钥 KEK 包装的 DEK 落盘
- [x] 用恢复密钥也能解开 DEK 包装（核心层验证，救援 UI 在 03）
- [x] 前端流程测试覆盖：生成 → 展示 → 错误重输被拒 → 正确重输 → 进入主界面
