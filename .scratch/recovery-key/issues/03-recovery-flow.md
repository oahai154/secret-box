# 03 — 救援流程：忘记主密码

**What to build:**
锁定界面提供"忘记主密码？"入口：警告告知流程与数据不变 → 输入恢复密钥 → 验证通过（成功解开 DEK 包装）→ 设置新主密码 → 重新包装 → 直接进入主界面。救援之外不设任何旁路：无密保问题、无验证码、无找回。依据 ADR-0003。

**Blocked by:** 02 — 恢复密钥生成与强制确认

**Status:** done

> 实施说明：
> - 核心层无新增：救援 = `unlock_with_recovery_key`（02）+ `change_password`（01）
>   组合，DEK 不变 → 恢复密钥侧包装原样保留，救援后恢复密钥继续有效。
> - Tauri 新增 `recover_password(recovery_key, new_password)`：与 change_password
>   的区别在于**在锁定状态下调用**（这正是它的用途）、凭恢复密钥而非旧主密码验证，
>   成功后把会话密钥置为 DEK 直接进入解锁态。错误恢复密钥报"恢复密钥不正确"，
>   到不了设新密码一步，无其他信息泄露。
> - 前端：新增 `RecoverView.svelte`（警告文案、恢复密钥、新主密码两遍、错误行、
>   返回解锁）；锁屏解锁模式下新增"忘记主密码？"入口（设置模式不显示）；
>   `App.svelte` 增加 `recovering` 状态分支，`handleSessionReset` 同步复位。
> - 测试：Tauri 端到端（锁定态拒绝读条目 → 输入校验/错误码拒绝 → 正确救援 →
>   数据完整 → 旧密码失效新密码可解锁 → 恢复密钥仍有效）；Playwright
>   `recovery-rescue.spec.ts` 四用例（入口、错误码、密码不一致、满血回归）。
> - 视觉基线：解锁页因新增"忘记主密码？"按钮有意偏离 Go 版基准（ADR-0003），
>   用 `tests/e2e/recapture-baseline.mjs`（本轮新增，替代随 Go 版删除的
>   capture-baselines 脚本）重截 `auth.png`；其余 8 张基线不变、原样通过。
